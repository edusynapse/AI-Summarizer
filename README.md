# AI-Summarizer

Canonical, repo-agnostic source of the **`agent_token_usage_optimization`**
skill — a token-reduction architecture for AI coding agents
(Claude, Codex, Antigravity, Cursor, Aider, …).

This repo is the **canonical source** of the skill. Install a copy of
`agent_token_usage_optimization/` into any project's `skills/` folder.
Improvements land here first, then propagate via `install.sh`.

## What's in the skill

Layers, each independently useful:

1. **Context Broker & Offloading Agent**
   - `broker.py` — symbol + source retrieval (`search`, `read --symbol`, `outline`, minified `diff`…)
   - `summary_broker.py` — **summary-layer-first** broker (preferred starting point; keyword, hotspots, **semantic**)
   - `low_tier_agent.py` — offload find-symbol / suggest-edit / search / agent-edit to cheaper models
2. **LLM Summary Cache (`summaries/`)** — provider-backed, hash-keyed, incremental
   file summaries (agy / grok parallel runners).
3. **Directory Rollups** — hash-keyed directory routing docs over file summaries.
4. **Layer 2 — Tiered context manager** — pinned / working / cold session board + budgeted `pack`.
5. **Layer 3 — Log/diff minifier** — shrink noisy diffs and logs before they enter context.
6. **Optional** — MCP stdio server, tree-sitter outlines, embeddings over the summary corpus.

Full architecture rationale is in `agent_token_usage_optimization/README.md`.

**Shared** files are byte-identical across every repo and are overwritten by
`install.sh`. **Per-repo** files (`config.json` in `repo/`,
`summaries/config.json`, `summaries/rollups_config.json`,
`summaries/embeddings_config.json`, and `repo_context/*.md` beyond the README)
are NEVER overwritten — see `install.sh` for the exact rule.

The broker database `skills/agent_token_usage_optimization/repo/index.sqlite`
is generated by `broker.py index` and should be committed when you want agents
to have symbol search immediately after checkout. Python bytecode (`__pycache__/`,
`*.py[cod]`) should stay ignored in each consumer repo.

## Requirements

- **Python 3.9+** (stdlib only for brokers/indexer; no pip package required)
- Optional LLM CLIs on `$PATH` for summarization / low-tier agents:
  - `agy` (Antigravity) + model **Gemini 3.7 Flash (Low)**
  - `grok` (xAI Grok CLI) + model **`grok-4.5`** (Composer is not used)
- Brokers and the symbol index work **without** an LLM once summaries exist
  (or if you only use `broker.py` against source)

## Install into a target repo

```bash
./install.sh /path/to/target_repo
```

First run: drops the full tree into `<target_repo>/skills/agent_token_usage_optimization/`.

Subsequent runs: overwrite shared files only. Per-repo configs and curated
`repo_context/` content are preserved.

### Agent instruction files: `CLAUDE.md` + `AGENTS.md`

The installer drops **two** files at the **target repo root** (not inside
`skills/`):

| File | Read by |
|---|---|
| `CLAUDE.md` | Claude Code; Antigravity when its agent is on a Claude model |
| `AGENTS.md` | Codex (VSCode + CLI); Antigravity (all models); Cursor; Aider |

Both are written from the **same template body** for full compatibility —
no per-file content drift. The runtimes auto-load these into the system
prompt at session start, so the "summaries-first, broker-for-symbols,
source-last" workflow applies without restating it.

#### Two profiles: loose (default) vs. strict

Static instruction files can't be model-aware at runtime (no runtime
exposes "the current model" to file loading). So the strategy is two
profiles, swapped per repo by a separate script:

| Profile | When to use | Body |
|---|---|---|
| **loose** (default) | High-capability models (Opus, Sonnet 4.6+, GPT-5, o-series, Gemini 2.5 Pro) | Suggested workflow, broker commands, "use judgment" |
| **strict** | Low-cost / smaller models (Haiku, GPT-4.1-mini, Gemini Flash) where wriggle room hurts more than it helps; or high-stakes repos where the workflow must be followed verbatim | Numbered required steps, hard "DO NOT" rules, stale-summary fallback |

`install.sh` writes the **loose** profile by default. Flip a repo with:

```bash
./switch-agent-type.sh low   /path/to/repo    # → strict
./switch-agent-type.sh high  /path/to/repo    # → loose
./switch-agent-type.sh check /path/to/repo    # report current profile + strays
./switch-agent-type.sh low   /path/to/repo --force   # bypass "custom file" prompt
```

`check` also scans the tree for stray `AGENTS*.md` / `CLAUDE*.md` files
in subdirectories — these are also read by some agents (notably Codex,
which walks from project root down to cwd), so they're worth knowing
about.

> **Heads up:** Instruction files are loaded once at session start, not
> per turn. After switching profile, **open a new conversation /
> session** in your IDE — current sessions stay on the old profile until
> they end. No IDE restart needed.

#### Template marker block

Template content is delimited by HTML markers so it can coexist with a
human-authored `CLAUDE.md` / `AGENTS.md`:

```markdown
<!-- BEGIN agent_token_usage_optimization -->
... skill guidance ...
<!-- END agent_token_usage_optimization -->
```

Install-time and switch-time behavior applies independently to each of
`CLAUDE.md` and `AGENTS.md`:

| Target state | Behavior |
|---|---|
| File missing | Create it from the active profile template. |
| File **with** the marker block | Refresh just the block in place — surrounding content untouched. This makes re-running `install.sh` / `switch-agent-type.sh` safe and idempotent. |
| File **without** the block, interactive shell | Warn + prompt: `[a]ppend` (add block at end) / `[o]verwrite` (replace whole file) / `[s]kip` (default). |
| File **without** the block, non-interactive shell | Warn + skip — no file modified. CI-safe. Pass `--force` (switch script only) to overwrite anyway. |

After install, in the target repo:

```bash
# 1. customize include/exclude rules
$EDITOR skills/agent_token_usage_optimization/repo/config.json
$EDITOR skills/agent_token_usage_optimization/summaries/config.json
$EDITOR skills/agent_token_usage_optimization/summaries/rollups_config.json

# 2. populate orientation (see repo_context/README.md for suggested files)
$EDITOR skills/agent_token_usage_optimization/summaries/repo_context/00_what_this_repo_is.md

# 3. build the symbol index (optional but useful)
python3 skills/agent_token_usage_optimization/broker.py index

# 4. backfill LLM summaries (the foundation for summary_broker.py)
# parallel runners — both parent-merge the manifest, so N workers are safe.
# agy: select the model ONCE via agy /model; the runner asserts it and never
# writes settings.json (see summaries/README.md).
PARALLEL=5 bash skills/agent_token_usage_optimization/summaries/run_agy_cli_summaries.sh
# or grok: bash skills/agent_token_usage_optimization/summaries/run_grok_cli_summaries.sh
# alternate serial: python3 …/summarizer.py --provider agy --model "Gemini 3.7 Flash (Low)"
python3 skills/agent_token_usage_optimization/summaries/rollup_summarizer.py
python3 skills/agent_token_usage_optimization/indexer.py

# Agents now have both brokers available:
#   summary_broker.py search ...     ← start here
#   broker.py search ...             ← when you need symbols
```

All commands below assume you are in the **target repo root** after install,
with paths relative to `skills/agent_token_usage_optimization/`.

## Daily usage (core brokers)

```bash
SK=skills/agent_token_usage_optimization

# Summary-first (keyword)
python3 $SK/summary_broker.py search "auth OR session" --dir src --max 25
python3 $SK/summary_broker.py hotspots scaling
python3 $SK/summary_broker.py grep "rate.?limit|cache invalidat"
python3 $SK/summary_broker.py read src/auth/session.py
python3 $SK/summary_broker.py rollup src
python3 $SK/summary_broker.py list lib

# Symbols / source slices (after broker.py index)
python3 $SK/broker.py search "createSession"
python3 $SK/broker.py outline path/to/file.ext    # prints backend=tree-sitter|regex
python3 $SK/broker.py read path/to/file.ext --symbol someFunction
python3 $SK/broker.py read path/to/file.ext --lines 40-80
python3 $SK/broker.py summary path/to/file.ext
python3 $SK/broker.py context --list
```

After large refactors: re-run the summarizer (incremental), rollups, then
`broker.py index` so the symbol DB matches current source.

## Layer 2 — tiered context manager (pinned / working / cold)

Keep a **session board** of paths so packed prompts stay under budget.

| Tier | Role | What `pack` includes |
|------|------|----------------------|
| **pinned** | Orientation + always-needed modules | Full summary / `repo_context` (budgeted) |
| **working** | Files actively under change | Prefer LLM summaries; optional source |
| **cold** | Known but not loaded | One-line stubs only |

State file (gitignored): `skills/.../repo/context_session.json`.

```bash
SK=skills/agent_token_usage_optimization
CM=$SK/context_manager.py

python3 $CM task "fix session expiry race"
python3 $CM seed-context                    # pin all repo_context/*.md
python3 $CM pin src/auth/session.py --note "expiry bug"
python3 $CM work src/auth/middleware.py
python3 $CM cold tests/auth/test_session.py
python3 $CM status
python3 $CM pack --budget 20000             # emit pack for the agent turn
python3 $CM pack --budget 20000 --source    # include source for working tier
python3 $CM promote path/to/file            # cold→working→pinned
python3 $CM demote path/to/file             # pinned→working→cold
python3 $CM rm path/to/file
python3 $CM clear working                   # or: clear  (entire session)
```

**When to use:** start of a multi-file task, or before a long edit, so the
model does not re-open the whole tree. Keep the working set small (about 3–8
paths); move finished paths to cold.

Deep dive: [docs/context_tiers.md](docs/context_tiers.md).

## Layer 3 — log / diff minifier

Shrink noisy diffs and logs before they enter the model context.

```bash
SK=skills/agent_token_usage_optimization
M=$SK/minify.py

# Diff (file or stdin). Stats on stderr; -q to silence.
git diff | python3 $M diff -
python3 $M diff /tmp/change.diff --max-hunk 60 --max-total 500
python3 $M diff - --full-context          # do not thin context lines

# Log
tail -n 5000 app.log | python3 $M log -
python3 $M log /tmp/app.log --max-lines 300
python3 $M log - --keep-debug             # keep DEBUG/TRACE
python3 $M log - --keep-timestamps --keep-noise

# Same minifier via broker (default); --raw = light strip only
python3 $SK/broker.py diff
python3 $SK/broker.py diff HEAD~3 --max-hunk 40
python3 $SK/broker.py diff --raw -q
```

**Diff minifier:** drops `diff --git` / `index` noise, caps hunk/file/total
lines, thins pure context, labels binaries without dumping them.

**Log minifier:** strips timestamps (optional), drops DEBUG/TRACE and
healthcheck-like noise by default, redacts UUIDs/long hex/request ids,
collapses consecutive identical lines (`×N`), keeps the **tail** when
truncating.

Deep dive: [docs/log_diff_minifier.md](docs/log_diff_minifier.md).

## Tree-sitter outlines (optional, higher accuracy)

`broker.py outline` and `read --symbol` use `lib/outline.py`:

1. **tree-sitter** when packages are installed → `backend=tree-sitter`
2. else original **regex** → `backend=regex`

```bash
# once per machine (user or venv)
pip install -r /path/to/AI-Summarizer/requirements-optional.txt
# installs: tree-sitter, tree-sitter-language-pack

# in the target repo — no reinstall of the skill required
python3 skills/agent_token_usage_optimization/broker.py outline path/to/file.dart
# FILE: …  lang=dart  backend=tree-sitter  symbols=N
```

**After installing tree-sitter (or fixing outline), re-run the symbol index**
so `broker.py search` uses the better names/lines. Summaries, rollups, and
embeddings do **not** need regeneration for outline-only changes:

```bash
python3 skills/agent_token_usage_optimization/broker.py index
```

Deep dive: [docs/tree_sitter_outline.md](docs/tree_sitter_outline.md).

## Embeddings semantic search (summary corpus)

Keyword search finds exact tokens. Semantic search ranks LLM summaries (and
rollups) by vector similarity so paraphrases still surface.

Default backend is **`hashing`** (stdlib-only, no API key). Better backends:
`openai`, `ollama`, `st` (sentence-transformers) — see config.

```bash
SK=skills/agent_token_usage_optimization

# after summaries exist under summaries/repo/
python3 $SK/embeddings_index.py build
python3 $SK/embeddings_index.py status
python3 $SK/embeddings_index.py search "session expiry middleware" --max 20
python3 $SK/summary_broker.py semantic "session expiry middleware" --max 20
python3 $SK/summary_broker.py semantic "…" --dir lib

# full re-embed after changing backend/model/dim
python3 $SK/embeddings_index.py build --force
```

Config (preserved on reinstall):

```text
skills/agent_token_usage_optimization/summaries/embeddings_config.json
```

Index files (gitignored): `summaries/embeddings/index.json` + `vectors.bin`.

Rebuild after large summary refreshes (`build` reuses unchanged SHA-1s). Env
overrides: `EMBED_BACKEND`, `EMBED_MODEL`, `OPENAI_API_KEY` / `EMBED_API_KEY`,
`OPENAI_BASE_URL`.

Deep dive: [docs/embeddings_semantic_search.md](docs/embeddings_semantic_search.md).

## Multi-repo (separate stores — mandatory model)

Each repo keeps its **own** `summaries/`, `repo/index.sqlite`, and `repo/adjacency.sqlite`.  
`workspace.env` only lists sibling paths; tools use `--repo <id>` to **read** that sibling’s stores. DBs are never merged.

```bash
./install.sh /path/to/app
./install.sh /path/to/api
./configure_workspace.sh /path/to/app --id app --role app --sibling api=/path/to/api
cd /path/to/app && python3 skills/…/broker.py index   # builds THIS repo adjacency only
python3 skills/…/summary_broker.py adjacent path/to/file
python3 skills/…/summary_broker.py --repo api search "…"
python3 skills/…/summaries/postprocess_summaries.py   # fix NAVIGATION lines + inject ADJACENT
```

See [docs/workspace_multi_repo.md](docs/workspace_multi_repo.md).

## Improvement workflow

1. Edit the shared files **here**, in this repo (especially `summary_broker.py` + `lib/summary_search.py`).
2. Test in one consumer repo (copy or symlink during iteration).
3. When stable, commit here.
4. Run `./install.sh <repo>` against each consuming repo to propagate.

Because `summary_broker.py` only reads the already-generated `summaries/` tree, it requires no changes to the summarizer pipeline.

Per-repo customization (configs, orientation files) stays in the consuming
repos — never push it back here.
